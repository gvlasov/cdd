Автоматическая отрисовка онтологии

Как автоматически разместить блоки и провести между ними разные типы связей так, чтобы схема оставалась читаемой.

Вывод. Задача решаема существующими JavaScript-инструментами. Для онтологии CDD наиболее подходящая базовая комбинация — ELK.js для размещения и трассировки + Cytoscape.js для просмотра либо React Flow для редактирования. Идеальность не гарантируется для произвольного графа: цель алгоритма — хороший, а не абсолютный оптимум.

1. Что именно рисуется

Модель — ориентированный типизированный граф. Узлы: concept, process, stakeholder, problem, reflection. Рёбра имеют смысл и вид: например, «является отражением», «участвует в процессе», «решает проблему», «зависит от».

Координаты и точки изгиба не должны быть источником истины: это результат вычисления из семантического графа. Однако пользовательские закрепления и ручные поправки стоит хранить как overrides.

2. Математическая осуществимость и границы

  • Если граф планарный, его можно нарисовать без пересечений; это можно проверить эффективно.
  • Произвольный граф может быть непланарным: полностью убрать пересечения тогда невозможно.
  • Минимизация числа пересечений, длин рёбер, площади и числа изгибов — конфликтующие цели. Для общего случая точная оптимизация вычислительно трудна, поэтому production-движки применяют эвристики.
  • Циклы допустимы. Иерархический алгоритм временно разворачивает часть рёбер для раскладки, а затем рисует их как обратные обходные связи.

Следовательно, нужно проектировать не «автоматический рисунок без ошибок», а управляемый layout: семантические приоритеты, группировка, фильтрация связей, фиксированные узлы и несколько режимов обзора.

3. Словарь области

ТерминЗначение и применение
Graph drawing / automatic layoutАвтоматическое построение геометрии графа.
Layered / Sugiyama layoutУзлы идут по слоям в одном направлении; подходит для зависимостей и онтологии.
Cycle breakingВременное обращение части рёбер для работы со слоями в циклическом графе.
Crossing minimizationУпорядочивание узлов внутри слоя, уменьшающее пересечения.
Force-directed layoutСиловая модель: связанные узлы притягиваются, остальные отталкиваются; хороша для обзорной карты сети.
Compound graphГраф с вложенными группами/контейнерами.
Ports / anchorsФиксированные точки на границе блока, к которым присоединяются рёбра.
Orthogonal routingПрокладка линий под прямыми углами вокруг блоков.
Incremental layoutРаскладка, стремящаяся не разрушать уже знакомую пользователю картину.

Рекомендуемая реализация

Начать с ELK Layered: направление слева направо, ортогональные стрелки, порты на сторонах карточки, различимый стиль для обратных/второстепенных связей.

Для просмотра использовать Cytoscape.js; для ручного построения и редактирования — React Flow + тот же ELK.js. Добавить закрепление узлов, сворачивание групп и фильтр типов рёбер. Для плотных неиерархических связей дать отдельный force-directed режим.

5. Реалистичная оценка покрытия

Библиотеки закроют примерно 80–90% технической части: размещение блоков, прокладку линий, взаимодействие, масштабирование и стили. Оставшиеся 10–20% — ключевая доменная работа: правила приоритета связей, семантические группы, устойчивость схемы при изменениях и UX для очень плотных подграфов.
